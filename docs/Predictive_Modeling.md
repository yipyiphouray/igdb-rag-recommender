# Content-Based Similarity Methodology

## 1. Overview

The recommendation layer now uses a fully decoupled content-based approach instead of a Random Forest predictive model. Recommendations are generated by computing cosine similarity between:

1. A user questionnaire profile.
2. A game feature profile built from IGDB metadata.

This design keeps ranking interpretable, deterministic, and resilient to sparse labels.

## 2. Core Similarity Flow

For each game, we build a feature vector using:

* Platforms
* Genres
* Themes
* Normalized rating signal (`total_rating / 100`)
* Optional scoring metadata used after cosine (playtime, release year)

For the user, the questionnaire is converted into a parallel feature vector from:

* `platforms`
* `genres`
* `themes`
* target `rating`
* optional controls (`discovery`, `quality_weight`, `playtime`, `years_mode`, etc.)

The base score is standard cosine similarity between the user vector and each game vector.

## 3. Discovery Modes

The `discovery` field supports:

* **Balanced**: Standard feature weighting.
* **Niche**: Rare genres/themes get extra weight using inverse-frequency style rarity values over the catalog.
* **Popular**: Increases influence of rating alignment in the user vector to bias toward high-rated mainstream candidates.

## 4. Quality, Playtime, and Years Weights

After cosine, the final score applies multiplicative controls:

* **Quality multiplier**: Rewards games whose `total_rating` is close to the user target rating.
* **Playtime multiplier**: Matches `playtime_normally` against:
  * `Short`: `<= 10` hours
  * `Medium`: `> 10 and <= 30` hours
  * `Long`: `> 30` hours
* **Years control** for the 2010-2024 window:
  * `boost`: boost in-range games and down-weight out-of-range games.
  * `filter`: exclude out-of-range games.
  * `off`: no year adjustment.

Final ranking is by `final_score` (then cosine, then rating for tie-breaks).

## 5. Missing Metadata Safety

The recommender is NaN-safe by design:

* Missing text metadata (platforms/genres/themes) is treated as empty.
* Missing numeric metadata (`total_rating`, `playtime_normally`, `release_year`) falls back to safe defaults.
* No recommendation step raises errors from null/NaN fields; missing values only reduce feature overlap and confidence.

## 6. Retrieval Validation

Seed-based retrieval validation has been run on cooperative game scenarios and is producing strong ranking behavior.

* Using a cooperative seed title such as `It Takes Two`, the retrieval pipeline first narrows the candidate pool to feature-similar games before hybrid ranking.
* Ranked outputs consistently prioritize:
  * shared/cooperative mechanics, and
  * developer continuity signals (via metadata boost for overlapping developers).

This confirms the practical effectiveness of attribute-constrained retrieval for co-op discovery workflows.
